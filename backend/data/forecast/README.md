# Delivery-delay forecasting dataset

`po_line_features.csv` is the tabular training set for comparing XGBoost, LightGBM and
CatBoost. Regenerate it (and the raw documents in `history/`, which are not committed) with:

```bash
cd backend
python -m scripts.build_forecast_dataset              # dataset only
python -m scripts.build_forecast_dataset --benchmark  # needs xgboost lightgbm catboost
```

## Source

A synthetic history (Jan 2024 to Feb 2026, 25 vendors, 8 construction categories) generated by
`forecasting/synthetic_history.py` in the same document shapes as `backend/data/*.json`, followed
by the hand-written demo corpus in `backend/data/` (March to April 2026). The three demo vendors
(Northstar, Apex, Kaveri) appear in both, so their demo POs come with a real track record.

## Grain and targets

One row per PO line (`po_id`, `line_no`).

| column | meaning |
|---|---|
| `delay_days` | received date minus promised date (PO date + contract `delivery_days`); negative = early |
| `is_late` | 1 if `delay_days > 0` |
| `received_shortfall` | line was closed short (invoiced without the full quantity received) |

Lines still open at the end of the data have empty targets: drop them for training, keep them
for scoring.

## Features

Listed in `forecasting/features.py` (`FEATURE_COLUMNS`). Groups: order size and value, calendar
(month, quarter-end distance, monsoon delivery window), contract terms (promised lead days,
penalty %, contract age), vendor load at order time (open POs and value), vendor delivery history
(lifetime, last, EWM, 90-day, trend, shortfall rate), vendor invoice anomaly rate, SKU and
category delay history.

`vendor_id`, `vendor_category` and `sku` are raw categorical columns so each library can use its
own native categorical handling.

## Leakage

Every feature is computed as of the PO date: history counts only lines whose outcome was known
strictly before it, and invoices dated strictly before it. Evaluate with
`forecasting.features.time_split(df, cutoff)`, which trains only on labels known before the cutoff
and tests on POs placed after it. Do not use a random split.
